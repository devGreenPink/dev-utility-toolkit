จำลอง:
Hook Reference
Change Detection (CD)
Angular ตรวจ state ของ app ว่ามีอะไรเปลี่ยนไหม แล้ว update DOM ให้ตรงกัน CD run ทุกครั้งที่มี event (click, HTTP response, setTimeout, Observable emit)
hooks ที่มี "ทุก CD cycle" = run บ่อยมาก: ระวัง performance
Content vs View
Content = HTML ที่ parent ส่งมาผ่าน <ng-content>  View = template ของ component เอง และ child components
ngAfterContent* → Content พร้อม  |  ngAfterView* → View + children พร้อม
@Input binding
ค่าที่ parent ส่งเข้า component ผ่าน [prop]="value": Angular ตรวจ reference change เท่านั้น object/array เดิมที่ mutate ภายในจะไม่ trigger ngOnChanges
ใช้ immutable update (spread) เพื่อให้ ngOnChanges fire: [...arr, item]
Fetch Data ใน ngOnInit
ไม่ใช่ constructor: @Input พร้อมแล้ว, testable กว่า
ngOnInit(): void {
  this.userId = this.route.snapshot.params['id'];
  this.user$ = this.userService.getUser(this.userId);
}
Cleanup ด้วย takeUntil (ngOnDestroy)
Pattern มาตรฐาน: unsubscribe ทุก Observable ใน ngOnDestroy
private destroy$ = new Subject<void>();

ngOnInit(): void {
  this.data$.pipe(
    takeUntil(this.destroy$)
  ).subscribe(d => this.data = d);
}

ngOnDestroy(): void {
  this.destroy$.next();
  this.destroy$.complete();
}
ViewChild ใน ngAfterViewInit
เข้าถึง DOM / child component ได้ที่นี่เท่านั้น: ไม่ใช่ ngOnInit
@ViewChild('canvas') canvasRef!: ElementRef;

ngAfterViewInit(): void {
  // DOM ready
  const ctx = this.canvasRef.nativeElement;
  this.chart = new Chart(ctx, this.config);
}
React ต่อ @Input Change
ใช้ ngOnChanges: แยก firstChange กับ update ออกจากกัน
ngOnChanges(changes: SimpleChanges): void {
  if (changes['config'] && !changes['config'].firstChange) {
    this.applyConfig(changes['config'].currentValue);
  }
}
เข้าถึง @ViewChild ใน ngOnInit
ย้ายไป ngAfterViewInit: DOM ยังไม่พร้อมใน ngOnInit
HTTP call ใน constructor
ย้ายไป ngOnInit: @Input พร้อม + testable กว่า
Heavy logic ใน ngDoCheck / ngAfterViewChecked
hooks เหล่านี้ run ทุก CD cycle: ใส่แค่ O(1) operation
ลืม unsubscribe ใน ngOnDestroy
ใช้ takeUntil(destroy$) หรือ AsyncPipe: ป้องกัน memory leak
detectChanges() ใน ngAfterViewChecked
Infinite loop: CD → hook → detectChanges → CD → ...
Mutate @Input object/array โดยตรง แล้วรอ ngOnChanges fire
ใช้ immutable: [...arr, item] หรือ {...obj, key: val}
